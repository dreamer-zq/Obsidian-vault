# Agent Memory 系统设计

记忆模块是 Agent 打破 LLM 上下文窗口限制、实现持续学习和个性化的关键。设计上通常模仿人类的记忆机制，分为**短期记忆**和**长期记忆**。

## 1. 记忆系统总览

```
┌──────────────────────────────────────────────┐
│              Agent Memory                    │
├──────────────────────────────────────────────┤
│                                              │
│  短期记忆 (Short-Term)                        │
│   ├─ 对话历史 Buffer                          │
│   ├─ Scratchpad（Thought-Action-Obs 轨迹）   │
│   └─ 上下文窗口                               │
│                                              │
│  长期记忆 (Long-Term)                         │
│   ├─ 向量数据库（语义检索）                    │
│   ├─ 知识图谱（关系查询）                      │
│   ├─ SQL/KV 数据库（结构化查询）              │
│   └─ 用户偏好 / 经验日志                       │
│                                              │
└──────────────────────────────────────────────┘
```

## 2. 短期记忆

### 2.1 作用

存储**当前任务的上下文信息**：

- 即时对话历史
- 中间思考步骤（ReAct 的 Scratchpad）
- 工具调用结果
- 临时计算结果

它是 Agent 进行**连贯思考和行动**的基础。

### 2.2 实现方式

#### (A) LLM 的上下文窗口

最直接的短期记忆载体——把所有最近交互直接放入 Prompt。

#### (B) 三种 Buffer 策略

| Buffer 类型 | 行为 | 适用场景 |
| :--- | :--- | :--- |
| **ConversationBufferMemory** | 完整保存所有历史 | 短对话、需要完整上下文 |
| **ConversationBufferWindowMemory** | 仅保留最近 K 轮 | 长对话、关注最新上下文 |
| **ConversationSummaryBufferMemory** | 超长时用 LLM 摘要 | 长对话且需要历史脉络 |

#### (C) Scratchpad（暂存器）

记录 ReAct 框架下的 `Thought → Action → Observation` 轨迹，是 Agent 进行逐步推理的核心载体。例如：

```
Thought: 我需要查询新加坡天气
Action: search("weather Singapore")
Observation: 晴天，32°C
Thought: 信息已获取，可以回答用户
```

## 3. 长期记忆

### 3.1 作用

存储**跨任务、跨会话**的信息：

- 用户的个人偏好（"我喜欢喝美式咖啡"）
- 过去的成功/失败经验
- 领域知识、文档库
- 用户的历史画像

让 Agent 能够"学习"和"成长"。

### 3.2 核心范式：RAG

长期记忆的核心是**存储**和**检索**，主流方案是 RAG（Retrieval-Augmented Generation）。

```
┌─────────────────────────────────────────────┐
│   ① 存储（Write）                             │
│   有价值的文本 → Embedding 模型 → 向量         │
│   ↓                                         │
│   向量 + 原文 → 写入向量数据库                  │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│   ② 检索（Read）                              │
│   当前任务/问题 → Embedding 模型 → 查询向量    │
│   ↓                                         │
│   向量库相似度搜索 → Top-K 相关记忆            │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│   ③ 使用（Use）                               │
│   Top-K 文本 → 注入 Prompt → LLM 决策         │
└─────────────────────────────────────────────┘
```

### 3.3 向量数据库选型

| 工具 | 类型 | 特点 |
| :--- | :--- | :--- |
| **Pinecone** | 云服务 | 全托管，企业级，付费 |
| **Weaviate** | 开源/云 | 支持混合检索（向量+关键词） |
| **ChromaDB** | 开源 | 轻量易用，本地友好 |
| **FAISS** | 开源库 | Facebook 出品，性能极强，需自建 |
| **Milvus** | 开源 | 大规模分布式向量搜索 |
| **Qdrant** | 开源/云 | Rust 编写，高性能 |

### 3.4 非向量长期记忆

并非所有信息都适合向量化：

| 存储类型 | 适用数据 | 检索方式 |
| :--- | :--- | :--- |
| **向量数据库** | 非结构化文本/语义查询 | 相似度搜索 |
| **SQL / 关系库** | 结构化数据（订单、用户） | SQL 精确查询 |
| **知识图谱**（Neo4j） | 实体关系网络 | 图遍历 / Cypher 查询 |
| **KV 存储**（Redis） | 高频读写的简单键值 | 直接查找 |
| **文档数据库**（MongoDB） | 半结构化嵌套数据 | 文档查询 |

## 4. 短期 vs 长期记忆对比

| 维度 | 短期记忆 | 长期记忆 |
| :--- | :--- | :--- |
| 存储位置 | LLM 上下文窗口 / Buffer | 外部数据库 |
| 持久性 | 会话结束即丢失 | 跨会话保留 |
| 容量 | 受窗口大小限制 | 几乎无限 |
| 访问方式 | 直接注入 Prompt | 需要检索后再注入 |
| 内容类型 | 当前任务的过程信息 | 知识、经验、偏好 |
| 主要技术 | Buffer 管理、摘要 | RAG、向量库 |

## 5. 工程实践要点

### 5.1 记忆写入的去重与质量控制

- 不要把所有对话都塞入长期记忆，需要**筛选有价值的信息**
- 重要的事件、用户明确表态、成功的解决方案优先入库
- 注意去重（同一偏好不必重复写入）

### 5.2 检索质量优化

- **Embedding 模型选型**：BGE、E5、Cohere、OpenAI text-embedding-3
- **Chunk 切分策略**：固定长度 / 语义切分 / 父子分块
- **混合检索**：向量 + BM25 关键词 + 重排序（Rerank）
- **过滤元数据**：按时间、用户、类型筛选

### 5.3 记忆更新与遗忘

- **写时去重**：写入前检查相似记忆
- **过期机制**：旧记忆降权或归档
- **反思（Reflection）**：周期性让 LLM 总结、合并、删除冗余记忆

## 6. 高级方案：分层记忆架构

参考 **MemGPT** / **Generative Agents** 论文：

```
┌──────────────────────────┐
│  Working Memory (主上下文) │ ← 当前活跃信息
└──────────────────────────┘
            ↑↓ 换入换出
┌──────────────────────────┐
│  Episodic Memory (事件库)  │ ← 重要事件日志
└──────────────────────────┘
            ↑↓ 反思总结
┌──────────────────────────┐
│  Semantic Memory (知识库)  │ ← 抽象出的知识
└──────────────────────────┘
```

## 7. 学习要点

- ✅ 短期记忆 = 上下文窗口 + Scratchpad；长期记忆 = 外部存储 + 检索
- ✅ RAG 是长期记忆的事实标准方案
- ✅ 不要只用向量库，**结构化数据用 SQL/图，非结构化用向量**
- ✅ 检索质量比 LLM 能力更影响 Agent 表现，工程优化空间巨大
- ✅ 进阶方向：分层记忆、反思机制、记忆遗忘
