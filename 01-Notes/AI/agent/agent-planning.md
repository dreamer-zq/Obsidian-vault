# Agent 规划能力分类

规划能力是衡量 Agent 智能水平的核心指标，它决定了 Agent 能否有效地将复杂目标分解为可执行步骤。当前主流方法按抽象层次和复杂度可分为三类。

## 1. 总览

```
┌────────────────────────────────────────────────┐
│            Agent 规划能力层次                   │
├────────────────────────────────────────────────┤
│                                                │
│  ① 基于提示的隐式规划                            │
│      CoT  →  ReAct                             │
│      (线性)   (动态线性)                        │
│                                                │
│  ② 基于搜索的显式规划                            │
│      ToT (树搜索)  →  GoT (图搜索)             │
│                                                │
│  ③ 基于任务分解的规划                            │
│      Planner-Executor 模式                     │
│                                                │
└────────────────────────────────────────────────┘
```

## 2. 基于提示的隐式规划

### 2.1 Chain of Thought（CoT，思维链）

- **核心**：在 Prompt 中加入 "Let's think step by step"，引导 LLM 生成线性思考过程
- **优点**：实现简单，无需修改模型
- **缺点**：
  - 线性单路径，无法探索/回溯
  - 某一步出错则整链路失败

### 2.2 ReAct

详细机制见 [[llm-agent-architecture]] 第 3 节。

- **核心**：CoT + 工具调用，"思考 → 行动 → 观察"循环
- **改进**：每一步基于最新观察重新规划，具备一定鲁棒性
- **本质**：动态的、交互式的 CoT

## 3. 基于搜索的显式规划

把规划问题形式化为搜索问题，通过探索多条路径寻找最优解。

### 3.1 Tree of Thoughts（ToT，思维树）

```
                  [初始问题]
                 /    |     \
              思路A  思路B  思路C
              /  \    |
           A1  A2  B1
           ⭐
           展开
        最有希望的节点
```

- **核心**：把规划过程构建为思维树，LLM 在每个节点生成多个候选思考分支
- **搜索算法**：BFS（广度优先）或 DFS（深度优先）
- **节点评估**：通常由 LLM 自己打分
- **优点**：支持探索、评估、回溯，适合需要深思熟虑的复杂问题
- **缺点**：计算开销大，因为要维护和评估整棵树
- **适用场景**：数学证明、复杂规划、创意写作

### 3.2 Graph of Thoughts（GoT，思维图）

```
        [子问题1]──┐
            │      │
            ↓      │ 合并
        [子问题2]──┴─→ [整合解]
            │           │
            ↓           ↓ 循环优化
        [子问题3]   [精炼解]
```

- **核心**：ToT 的进一步泛化，思维过程是图状的而非树状
- **两个关键扩展**：
  - **合并（Merge）**：不同思维路径可以汇合，把多个子问题的解组合
  - **循环（Cycle）**：思维过程可以迭代地精炼优化
- **优点**：更灵活，适合需要信息整合或迭代改进的问题
- **缺点**：结构和实现比 ToT 更复杂

### 3.3 ToT vs GoT 对比

| 维度 | ToT | GoT |
| :--- | :--- | :--- |
| 拓扑结构 | 树 | 图（允许环、合并） |
| 路径合并 | ❌ | ✅ |
| 迭代精炼 | ❌（只能扩展） | ✅（可循环） |
| 适用问题 | 多路径探索 | 复杂整合 + 迭代 |
| 实现复杂度 | 中 | 高 |

## 4. 基于任务分解的规划

### 4.1 Planner-Executor 模式

```
           [主任务]
              ↓
      ┌──────────────┐
      │  Planner LLM │ → 生成依赖图 / 步骤列表
      └──────────────┘
              ↓
      ┌──────────────┐
      │ Executor LLM │ → 逐一执行子任务
      └──────────────┘
```

- **方法**：训练或提示 LLM 充当"规划器"，将主任务显式分解为依赖图或步骤列表，再由"执行器"完成
- **优点**：结构清晰，进度可监控
- **缺点**：
  - 对 LLM 的分解能力要求高
  - 预先分解的计划缺乏对动态变化的适应性

### 4.2 典型框架

- **HuggingGPT** / **AutoGPT**：明确分阶段规划+执行
- **LangChain Plan-and-Execute**：先规划全局步骤，再逐步执行

## 5. 三类规划方法的选型

| 任务特征 | 推荐方法 |
| :--- | :--- |
| 简单单链推理 | CoT |
| 需要工具调用的多步任务 | ReAct |
| 需要探索多种方案 | ToT |
| 需要整合多源信息或迭代优化 | GoT |
| 任务结构稳定、子任务清晰 | Planner-Executor |
| 任务可能动态变化 | ReAct（避免预先分解） |

## 6. 学习要点

- ✅ 三层抽象：**隐式（CoT/ReAct）→ 搜索（ToT/GoT）→ 显式分解**
- ✅ ToT 与 GoT 的本质区别在于**是否允许合并与循环**
- ✅ 规划能力越强 = 计算成本越高，需要根据任务复杂度权衡
- ✅ 规划方法选型本质上是 **"探索空间复杂度"** vs **"执行成本"** 的取舍
