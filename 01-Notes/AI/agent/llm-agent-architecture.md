# LLM 智能体架构

## 1. 什么是 LLM Agent

一个基于 LLM 的智能体（Agent）是**能够自主理解环境、进行规划决策、并执行行动以达成特定目标的计算系统**。它把大型语言模型作为"大脑"或"中央处理器"，进行复杂的推理和决策。

与传统单次调用 LLM 不同，Agent 具备两个关键特征：

- **自主性**：可以独立选择下一步动作，无需人类逐步指挥
- **循环执行**：与环境/工具持续交互，直到任务完成

## 2. 四大核心组件

```
┌─────────────────────────────────────────┐
│             用户目标 / 环境              │
└─────────────────┬───────────────────────┘
                  ↓
       ┌──────────────────────┐
       │  ① Brain / LLM 大脑   │ ← 中央认知
       └──────┬───────┬───────┘
              ↓       ↓
   ┌──────────────┐ ┌──────────────┐
   │ ② Planning   │ │ ③ Memory     │
   │   规划模块    │ │   记忆模块    │
   └──────┬───────┘ └──────────────┘
          ↓
   ┌──────────────┐
   │ ④ Tool Use   │ → 与外部世界交互
   └──────────────┘
```

### 2.1 Brain（大脑 / 核心引擎）

- **组件**：一个强大的 LLM（GPT 系列、Gemini、Llama、Qwen 等）
- **作用**：理解目标、感知信息、推理决策、协调其他模块
- **要求**：通常需要指令跟随能力强、推理稳定的模型

### 2.2 Planning（规划模块）

- **组件**：可以是 LLM 内置能力（通过 CoT、ReAct 等 Prompt 激发），也可以是独立算法
- **作用**：把复杂目标分解为可执行子任务，并基于反馈动态调整
- **关键**：复杂任务能否完成，**规划质量是决定性因素**
- 详见 [[agent-planning]]

### 2.3 Memory（记忆模块）

- **组件**：外部数据库（向量库、KV 存储、SQL/图数据库）
- **作用**：突破 LLM 上下文窗口限制
  - **短期记忆**：当前对话、思考轨迹（Scratchpad）
  - **长期记忆**：跨会话的经验、用户偏好、领域知识
- 详见 [[agent-memory]]

### 2.4 Tool Use（工具使用模块）

- **组件**：外部 API、函数库、硬件接口
- **作用**：扩展 LLM 自身做不到的能力
  - 实时信息获取（搜索引擎、数据库）
  - 代码执行（Python 解释器、Shell）
  - 物理操作（机器人、IoT）
- 详见 [[agent-tool-use]]

## 3. ReAct 框架：Agent 的基础行为范式

ReAct（**Rea**son and **Act**）是当前最基础也最通用的 Agent 行为框架，它通过 Prompt 设计让 LLM 协同生成**推理轨迹**和**行动指令**。

### 3.1 核心思想

模仿人类解决复杂问题的方式："**思考 → 行动 → 观察 → 再思考**"的循环。

### 3.2 一轮循环的三个步骤

```
┌────────────────────────────────────────┐
│ ① Thought（思考）：                     │
│   "我需要查一下新加坡今天的天气，         │
│    应该用搜索工具。"                     │
└────────────────────────────────────────┘
                ↓
┌────────────────────────────────────────┐
│ ② Action（行动）：                      │
│   Action: [Search, "weather Singapore"]│
└────────────────────────────────────────┘
                ↓
┌────────────────────────────────────────┐
│ ③ Observation（观察）：                 │
│   "晴天，最高温 32°C"                   │
└────────────────────────────────────────┘
                ↓
       下一轮 Thought（带入新观察）
```

### 3.3 与 CoT 的关系

| 维度 | CoT | ReAct 中的 Thought |
| :--- | :--- | :--- |
| 推理时机 | 一次性生成所有步骤 | 每步行动前动态生成 |
| 信息来源 | 仅基于初始输入 | 基于最新观察结果 |
| 处理动态环境 | ❌ | ✅ |
| 错误修正 | ❌ | ✅ |

**结论**：ReAct 的 Thought 本质上是一种 **动态的、交互式的思维链**。

### 3.4 ReAct 的优势

- **可解释**：每一步的"思考"使得 Agent 行为透明
- **可纠错**：根据观察结果实时调整策略
- **可扩展**：天然支持工具集成，与 [[agent-tool-use]] 无缝结合

## 4. Agent vs 传统 LLM 应用的本质差异

| 维度 | 传统 LLM 应用 | LLM Agent |
| :--- | :--- | :--- |
| 调用模式 | 一次性请求-响应 | 循环执行直到目标达成 |
| 决策主体 | 人类（每次指令） | Agent 自主决策 |
| 环境交互 | 通常无 | 持续读写外部世界 |
| 状态维护 | 无状态 | 需要短期+长期记忆 |
| 错误处理 | 用户重试 | Agent 自主重试与修正 |

## 5. 学习要点

- ✅ Agent = LLM（大脑） + 规划 + 记忆 + 工具，缺一不可
- ✅ ReAct 是入门 Agent 必懂的基础范式
- ✅ 区分"调用 LLM"和"构建 Agent"：自主性 + 循环 + 工具是分水岭
- ✅ 各模块都可以独立深化研究（详见学习清单各分册）
